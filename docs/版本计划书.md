## 1. 版本目标

### 1.1 V1.0 一句话目标

> **验证「日常学习 → 单元考试 → 能力认证」三层闭环：让 100 个种子用户坚持学习 4 周以上，完成一次单元考试并获得可验证的电子证书。**

### 1.2 版本成功标准（可量化）

| 维度 | 指标 | V1.0 目标（发布后 30 天） |
|------|------|---------------------------|
| 体验闭环 | 注册用户完成「首课 → 完成 1 个单元 → 参加单元考试」的转化率 | ≥ 40% |
| 认证闭环 | 通过认证考试并获取证书的用户数 | ≥ 30 人（种子用户） |
| 留存 | D7 留存 | ≥ 25% |
| 习惯 | 周活跃用户中「≥3 天学习」占比（WAU3/WAU） | ≥ 35% |
| 质量 | 代码沙箱判题成功率（非用户代码错误导致） | ≥ 99% |
| 性能 | 页面首屏 < 2s；代码判题 P95 < 5s | 达标 |

### 1.3 版本范围

- **做**（对应 PRD P0）：日常学习闭环增强、单元考试、考试报告、能力图谱、认证考试、电子证书、排行榜基础版。
- **不做**（明确砍掉）：移动端原生 App、社区/UGC、B 端企业服务、广告、好友系统、成就徽章（P1 后置）。
- **技术债可接受项**：SQLite 单机部署（MVP 阶段）、证书电子版仅图片+编号验证（不接 CA）。

## 4. Sprint 详细计划

> 节奏：**双周迭代**；每个 Sprint 产出可演示的功能增量；每周一次演示，Sprint 结束做复盘。

### Sprint 0（09-28 ~ 10-11）：准备与架构基座

**目标**：为三层闭环打地基，明确数据模型与工程基线。

**交付物**：
- 数据模型扩展：Unit/Lesson/Exercise 增加 `exam_config`（考试组卷配置）；新增 `Exam`、`ExamSubmission`、`Certificate`、`SkillMap`、`Leaderboard` 表
- 考试组卷服务设计：按单元知识点抽题（客观题比例 70% + 代码题 30%）
- 排行榜设计：周结算 + 段位（青铜→白银→黄金→钻石），防刷（XP 获取速率限制）
- CI/CD 建立：后端 `go test` + 前端 `vue-tsc` + 构建产物上传
- 无 LLM 降级模式：Eino 调用失败回退静态题库，全链路验证
- 证书数据结构：证书编号生成规则（不可枚举）、防伪码、验证页 API

**验收标准**：新表迁移成功；测试基线绿；降级模式演示通过。

### Sprint 1（10-12 ~ 10-25）：日常学习闭环（→ M1）

**目标**：用户从注册到完成第一个单元，全程「学得进去、停不下来」。

**交付物**：
- 首页改造：今日目标进度环、streak 展示、推荐「今日 3 题」（联动自适应推荐）、打卡按钮与激励文案
- 学习日历（本月视图 + streak 记录）
- 每日目标设置（XP 或题数两档，参考多邻国目标设计）
- 排行榜基础版：XP 周榜 + 段位升降
- 解锁规则：单元内课时全部完成才解锁单元考试入口
- 前端：响应式布局适配移动端浏览器（为 PWA 铺路）

**验收标准**：新注册用户引导漏斗「注册→完成首课→达成首日目标」转化率 ≥ 60%；打卡后 streak 正确 +1，中断规则正确。

### Sprint 2（10-26 ~ 11-08）：单元考试系统（→ M2 前半）

**目标**：把现有「AI 随机考试」升级为「单元维度系统考试」。

**交付物**：
- 单元考试：按单元知识点组卷（8–12 题，选择 40% + 填空 30% + 代码 30%），固定题源（静态题库优先 + AI 补充）
- 考试计时器（建议 15 分钟/10 题）+ 到时自动提交
- 防作弊基础版：切屏警告（页面失焦记录）、题目/选项乱序
- 考试不扣心数（沿用现有逻辑），提交批处理接口（已有 ExamSubmit 扩展：关联 exam_id、记录时长）
- 重考规则：未通过 24h 冷却后可重考，取最高分

**验收标准**：单元考试全流程（进入→答题→提交→结果）无断点；组卷不重复、难度分布可配；切屏被记录。

### Sprint 3（11-09 ~ 11-22）：考试报告与自适应联动（→ M2）

**目标**：让考试结果「可解释、可行动」，并与学习路径联动。

**交付物**：
- 考试报告页：总分、正确率、分题型正确率、知识点掌握度（列表/雷达图雏形）、每题解析回看
- 错题自动回流错题本（含来源标记「考试」）
- 能力图谱 v1：按知识点聚合练习+考试数据，展示「未学/学习中/已掌握/薄弱」
- 自适应推荐联动：根据考试薄弱知识点，推荐对应复习课时与习题（增强现有 adaptive/recommend）
- 分数预测 v1（可选，若时间不足则 P1）：基于历史练习正确率与考试表现的通过概率预估

**验收标准**：一次考试后，能力图谱正确更新；薄弱知识点出现在「今日推荐」；错题本出现对应错题。

### Sprint 4（11-23 ~ 12-06）：能力认证与证书（→ M3 前半）

**目标**：打通「学完 → 考出 → 拿证」的最后一环。

**交付物**：
- 认证考试：课程级综合考试（覆盖全部单元，理论 + 代码实操，限时 45–60 分钟），触发条件 = 课程全部单元考试通过
- 能力等级划分：入门 / 进阶 / 熟练（按认证考试得分段位映射）
- 电子证书：姓名、等级、课程、日期、唯一编号 + 防伪二维码；证书生成（前端 Canvas/后端图片均可，MVP 优先前端生成 + 后端存证）
- 证书在线验证页：输入编号即可验证真伪与证书详情（公开只读页）
- 「我的证书」列表 + 社交分享（生成分享图）

**验收标准**：通过认证的用户可生成证书；验证页可查真伪；伪造编号返回「无效」；证书数据落库可追溯。

### Sprint 5（12-07 ~ 12-20）：打磨、性能与发布准备（→ M3 后半）

**目标**：稳定性、性能、合规达标，具备发布条件。

**交付物**：
- 全链路性能压测：代码沙箱 P95 < 5s、考试批量提交 < 3s、页面首屏 < 2s
- 沙箱加固：资源限额（CPU/内存/时长）、恶意代码检测、异常熔断
- 合规补齐：注册协议、隐私政策、AI 内容生成标识
- 种子内容扩充：Go/Python 课程补足单元考试与认证考试题库（静态题 + AI 生成人工抽检）
- 埋点与看板：注册/首课/单元完成/考试/认证漏斗埋点
- 用户反馈入口（问题上报）

**验收标准**：压测达标；安全自测通过；§1.2 成功标准指标全部可采集。

### 发布窗口（12-21 ~ 12-31）

- **12-21 ~ 12-27**：内部灰度（团队 + 30 名种子用户），收集崩溃与体验反馈，修复 P0 缺陷
- **12-28**：全量发布 V1.0（线上公告 + 种子用户活动：认证考试限时免费）
- **12-31**：发布复盘，输出 V1.1 迭代清单

## 6. 团队与资源需求

### 6.1 建议团队（4–6 人）

| 角色 | 人数 | 主要职责 |
|------|------|----------|
| 产品经理 | 1 | 需求细化、验收、埋点口径 |
| 后端工程师 | 1–2 | Go 服务、考试/认证/排行榜服务、沙箱加固 |
| 前端工程师 | 1–2 | Vue3 页面、考试/报告/证书 UI、响应式 |
| 设计（可兼职/外包） | 0.5 | 打卡/排行榜/证书视觉、游戏化动效 |
| 测试/质量 | 1（可后端兼任） | 考试流程、沙箱安全、回归 |

### 6.2 外部依赖

- **LLM 服务**：LLM_API_KEY（豆包/OpenAI），需保证配额；无 Key 环境全功能降级
- **部署**：单机 Linux + SQLite（MVP）；预留 PostgreSQL 迁移路径
- **证书防伪**：自建编号 + 二维码校验（无需 CA 证书服务，降低复杂度）

## 7. 风险与依赖管理

| 风险 | 影响 | 应对 |
|------|------|------|
| 考试组卷与 AI 生成结合导致质量不稳 | 用户信任 | 静态题源优先（人工校验），AI 仅补充；代码题一律跑测试用例验证 |
| 沙箱安全/性能不过关（S5 才发现） | 发布延期 | S0 建立性能基线；S2 起每周沙箱压测；预留 1 周缓冲 |
| 证书设计返工（防伪/验证） | S4 延期 | S0 先定证书数据结构与编号规则；UI 与后端解耦 |
| LLM 服务不可用 | 体验降级 | S0 完成无 LLM 降级链路；生成失败重试与限流 |
| 3 个月内内容（题库）不足 | 考试可玩性低 | AI 生成 + 人工抽检滚动补齐；每 Sprint 完成 1 轮题库扩充 |
| 种子用户不足 | 无法验证闭环 | 发布前 2 周启动种子招募（开发者社区/高校社团）；给认证免费额度激励 |
