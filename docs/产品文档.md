## 1. 产品概述

### 1.1 产品愿景

> **让每一个零基础的成年人，都能像玩游戏一样坚持学编程，并通过考试认证获得「拿得出手」的能力证明。**

CodeLearn 是一款面向成人零基础自学的编程学习平台，融合 **多邻国（Duolingo）式游戏化日常学习** 与 **粉笔（Fenbi）式考试认证闭环**，提供「日常学习 → 单元考试 → 能力认证」三层递进的学习体验。

### 1.2 产品定位

- **一句话定位**：编程界的「多邻国 + 粉笔」——学得下去（游戏化）、测得出来（单元考试）、拿得出手（能力认证）。
- **核心差异化**：当前市场中没有产品同时具备「游戏化日常学习 + 编程考试认证 + AI 原生教学」三要素的组合能力（详见第 4 章竞品分析）。
- **目标人群**：成人零基础自学编程者（转行求职者、在职提升者、在校学生）。
- **当前产品形态**：Web 应用（Go + Gin + SQLite 后端，Vue 3 前端），后续演进为移动端优先（PWA → App）。

### 1.3 产品价值主张

| 用户痛点 | CodeLearn 的解法 |
|----------|------------------|
| 学编程坚持不下去、三天打鱼两天晒网 | 多邻国式游戏化：XP、连续打卡（streak）、心数（hearts）、排行榜、每日目标 |
| 不知道学得怎么样、学到哪一步 | 单元考试 + 能力图谱 + 成绩报告，每阶段可量化检验 |
| 学了没凭证、求职拿不出手 | 能力认证 + 电子证书（可在线验证），对标 Duolingo English Test / 粉笔考试体系 |
| 课程枯燥、不会的没人问 | AI 原生教学：AI 生成习题、AI 编程导师、知识点问答（RAG）、自适应路径 |

## 2. 市场分析

### 2.1 市场规模与趋势

- **中国编程语言学习平台市场**：2025 年市场规模约 **128.6 亿元，同比增长 19.3%**，增速显著高于在线教育整体（约 11.7%）；预计 2026 年达 153.4 亿元。数据来源：第三方市场研究机构（博研咨询/市场调研在线网），口径需在立项前进一步验证 [参考](https://www.docin.com/touch_new/preview_new.do?id=4968911668)。
- **用户结构**：新增注册用户中 18–25 岁占 43.6%，26–35 岁在职开发者占 31.2%，二者合计贡献约 74.8% 的付费收入；个人客单价从 2025 年的约 386 元/年提升至 2026 年预估 452 元/年 [参考](https://www.docin.com/touch_new/preview_new.do?id=4968911668)。
- **全球视角**：全球开发者缺口预计 2030 年达 8500 万个未填补岗位，编程学习需求长期旺盛 [参考](https://www.upskillist.com/blog/best-platforms-learning-coding/)。
- **认证需求政策驱动**：工信部「数字技术工程师培育项目」对 Python 等编程能力认证提出强制性要求，中高级编程能力认证培训需求被直接拉动 [参考](https://www.docin.com/touch_new/preview_new.do?id=4968911668)。
- **AI 融合加速**：2025 年已有 41 家平台启动 AI 辅助编程教学系统适配，17 家完成大模型本地化部署进入商业化验证，行业正从「录播 + 题库」向「实时代码诊断 + 项目级仿真环境」跃迁 [参考](https://www.docin.com/touch_new/preview_new.do?id=4968911668)。

### 2.2 关键市场信号（对 CodeLearn 的意义）

1. **游戏化留存被验证有效**：多邻国 2022 年上线排行榜后，用户总学习时间提升 17%，高投入学习者数量增长 2 倍 [参考](https://m.thepaper.cn/newsDetail_forward_30911231)。
2. **认证是重要变现与信任手段**：多邻国英语测试（DET）2025 年为公司贡献约 1.4 亿美元收入，被 6000+ 高校项目接受；粉笔以「考试培训 + 分数预测」构建商业闭环 [参考](https://canvasbusinessmodel.com/products/duolingo-business-model-canvas) [参考](https://spa.fenbi.com/page/qiyejieshao)。
3. **AI 正在成为教学核心**：多邻国用 Birdbrain 模型做自适应难度，用 AI 生成 148 门新课程；粉笔发布自研公考垂域大模型与 AI 老师 [参考](https://canvasbusinessmodel.com/products/duolingo-business-model-canvas) [参考](https://app.xinhuanet.com/news/article.html?articleId=0e2133d29d05c10aeef566c6de8170fe)。
4. **免费内容占据心智**：freeCodeCamp 完全免费、项目制认证，已帮助 4 万+ 人获得开发者工作，是成人编程学习的「免费底线」[参考](https://mentorcruise.com/blog/freecodecamp-vs-codecademy-which-actually-gets-you-hired-42fd4/)。

## 3. 目标用户与用户画像

### 3.1 目标人群

成人零基础自学编程者，主要分为三类：

#### 画像 A：职场转行者「小杨」
- **基本信息**：25 岁，互联网运营岗，工作 2 年，想转行数据分析/开发。
- **学习场景**：工作日下班后 20–30 分钟碎片化学习，周末 1–2 小时。
- **核心诉求**：① 路径清晰不迷路；② 强激励对抗惰性；③ 学完后有可量化的成果（证书/项目）。
- **付费意愿**：愿意为「效率 + 结果」付费，可接受 ¥30–60/月。

#### 画像 B：在校学生「阿哲」
- **基本信息**：22 岁，非 CS 专业大四学生，正在准备秋招/考研复试。
- **学习场景**：白天碎片时间 + 晚上集中练习。
- **核心诉求**：① 快速掌握一门语言（Python/Go）并输出作品；② 获得能被企业/面试官认可的能力证明；③ 预算有限。
- **付费意愿**：低月费或按次付费（认证考试费）。

#### 画像 C：在职提升者「林姐」
- **基本信息**：32 岁，传统行业测试工程师，想提升 Python 自动化脚本能力。
- **学习场景**：每周 3–4 次，每次 15–30 分钟，习惯用手机。
- **核心诉求**：① 内容实用、直接可迁移到工作；② 知道自己的薄弱点；③ 证书对企业晋升/跳槽有背书价值。
- **付费意愿**：中，为认证和 AI 辅导付费。

### 3.2 用户旅程痛点

| 阶段 | 痛点 |
|------|------|
| 入门 | 不知道从哪开始、环境搭建劝退、教程太多选择困难 |
| 学习 | 坚持不下去（最大痛点）、枯燥、缺乏反馈、无人答疑 |
| 检验 | 不知道掌握度、学完就忘、没有阶段目标 |
| 产出 | 没有作品/证书，求职时无法证明能力 |

## 4. 竞品分析

### 4.1 竞品全景图

按「游戏化程度 × 认证/考试完整度」划分竞争象限：

```
                认证/考试能力
                    高
        ┌─────────────────────────────────┐
        │  力扣(面试认证)  粉笔(考试认证)     │
        │  牛客(笔试面试)                     │
        │         ●●●●                      │
        │       ●      ●                    │
        │     ●   CodeLearn 目标位置  ●      │
        │       ●      ●                    │
        │         ●●●●                      │
        │   freeCodeCamp  DataCamp          │
        │   Codecademy   慕课网/极客时间       │
        │                                     │
        │  Duolingo   Mimo   SoloLearn       │
        │   (语言学习标杆) (编程版多邻国)        │
        └─────────────────────────────────┘
     低   游戏化与日常学习强度            高
```

**结论**：右上象限（高游戏化 + 高考试认证）在**编程**领域基本空白。多邻国游戏化最强但只做语言；粉笔考试认证最强但无编程且非游戏化；Mimo/SoloLearn 有游戏化但无考试认证；力扣/牛客有考试但面向求职刷题而非系统教学。

### 4.4 SWOT 分析

| | 有利因素 | 不利因素 |
|--|----------|----------|
| **内部** | **S（优势）**：AI 原生架构（Eino 已实现习题生成/自适应/导师/RAG）；代码沙箱（Go/Python 在线运行判题）；游戏化基础（XP/streak/hearts）；全栈技术栈完整 | **W（劣势）**：仅 2 门课程、内容规模小；无移动端；无品牌与用户基础；认证无第三方背书；无社区/UGC |
| **外部** | **O（机会）**：市场 19.3% 高增速；能力认证政策驱动（工信部数字技术工程师）；AI 教育融合窗口期；「游戏化+认证」编程领域空白；B 端测评市场 18.9% 占比并上升 | **T（威胁）**：Mimo/SoloLearn 移动端深耕；freeCodeCamp 免费心智；力扣/牛客的求职认知垄断；多邻国可能切入编程赛道；AI 编程助手降低学习门槛的长期冲击 |

### 4.5 差异化策略

1. **做「学得完」的事**：不追求题库规模（力扣 4900+ 题），而是靠 AI 生成 + 有限优质课程，把「每日 15 分钟」体验做到极致（对标多邻国）。
2. **补齐「认证」缺口**：Mimo/SoloLearn 都没有可信认证，CodeLearn 用「能力图谱 + 认证考试 + 可验证电子证书」建立差异化信任。
3. **AI 原生而非 AI 点缀**：AI 习题生成、AI 导师、AI 批改、自适应路径全部原生集成（区别于把 AI 做成插件的竞品）。
4. **考试不含糊**：借鉴粉笔「学-练-测-评」闭环，单元考试不扣心数、有报告、错题回流错题本，形成数据闭环。

## 5. 功能需求

### 5.1 信息架构

```
CodeLearn
├── 首页（今日任务 / 每日打卡 / 连续天数 / 推荐路径）
├── 学习路径（课程 → 单元 → 课时 → 习题）
│   ├── 单元考试（单元解锁后开放）
│   └── 阶段模考（课程级）
├── 练习（AI 生成练习 / 错题本 / 知识点练习）
├── AI（编程导师 / 知识点问答）
├── 考试中心（单元考试 / 认证考试 / 历史成绩）
├── 能力认证（能力图谱 / 认证考试 / 我的证书）
├── 排行榜（段位 / 每周结算）
└── 个人中心（统计 / 设置 / 订阅）
```

### 5.2 功能需求列表

> 优先级说明：**P0** = MVP 必须（对应版本计划 M1–M3）；**P1** = 发布后第一个迭代周期；**P2** = 远期。

#### 模块一：日常学习（对标多邻国）

| 编号 | 功能 | 优先级 | 需求描述 | 现状 |
|------|------|--------|----------|------|
| F-L1 | 每日目标与打卡 | **P0** | 用户可设置每日目标（XP/题数），首页显示进度环，完成后打卡；连续打卡天数（streak）展示与延续逻辑 | 部分：已有 DailyGoal/StreakDays，缺打卡引导 UI |
| F-L2 | 技能树学习路径 | **P0** | 课程→单元→课时 解锁式闯关，前置完成才能解锁 | 已实现 |
| F-L3 | 多题型练习 | **P0** | 选择题、填空题、代码编写题；代码题在线运行 + 测试用例判题（Go/Python） | 已实现 |

### 5.3 核心用户流程

**流程一：日常学习闭环（每日 15 分钟）**

```
打开首页 → 查看今日目标(进度环/streak) → 进入推荐课时
  → 学知识点(图文) → 练 2-3 题(选择/填空/代码)
  → 错题自动进错题本 → 完成课时得 XP
  → 达成今日目标 → 打卡成功 → streak +1
```

**流程二：考试认证闭环**

```
完成单元全部课时 → 解锁单元考试 → 系统组卷(限时)
  → 提交(不扣心数) → 生成考试报告(知识点掌握度)
  → 未通过：错题进错题本 + 24h 后重考
  → 通过：能力图谱更新 → 解锁下一单元
        ── 课程全部单元通过 ──► 解锁认证考试
  → 通过认证 → 颁发电子证书(编号+防伪码) → 分享/验证
```

| 类别 | 要求 |

## 8. 核心指标

### 8.1 北极星指标

> **每周完成 ≥3 天有效学习（每日 ≥15 分钟或达成每日目标）的活跃学习者数量（WAU3）**

选择理由：同时衡量「日常学习习惯」（多邻国式留存）与「学习价值」（有效时长），是订阅转化与考试参与的前提。

### 8.2 指标体系

| 类型 | 指标 | 目标（发布后 90 天） |
|------|------|----------------------|
| 转化 | 注册 → 首课转化率 | ≥ 60% |
| 留存 | D1 / D7 / D30 留存 | ≥ 45% / ≥ 25% / ≥ 15% |
| 习惯 | WAU3 / MAU | ≥ 35% |
| 参与 | 单元考试参与率（完成单元的用户的报考比例） | ≥ 70% |
| 参与 | 单元考试一次通过率 | ≥ 50%（难度校准用） |
| 变现 | 认证考试报名率 / 通过率 | ≥ 40% / ≥ 60% |
| 变现 | 免费 → Pro 订阅转化率 | ≥ 3% |
| 内容 | 平均每课 AI 习题生成使用率 | ≥ 30% |

## 9. 风险与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| 认证缺乏第三方权威背书，求职认可度低 | 高 | MVP 阶段以「能力图谱 + 可验证证书」建立产品内信任；P2 与行业机构/企业合作背书；证书验证页透明可信 |
| 内容规模小（仅 Go/Python 各 3 单元） | 高 | 用 AI 生成扩题量；课程内容快速扩展 JS/SQL；以「深度+AI 扩展」对抗「广度」 |
| 多邻国等大厂切入编程赛道 | 中 | 聚焦「编程 + 认证」垂直纵深，先发建立认证与题库数据闭环 |
| AI 生成习题质量不稳定 | 中 | 答案校验（代码题跑测试用例）、人工抽检、用户反馈标记；LLM 降级策略 |
| 免费替代品（freeCodeCamp 等）压制定价 | 中 | 差异化在「游戏化坚持 + 考试认证结果」，不拼免费内容堆量 |
| 代码沙箱安全风险（逃逸/资源滥用） | 高 | 容器级隔离、资源限额、超时熔断、恶意代码检测；考试代码题限制执行次数 |
| 用户时间碎片化导致完成率低 | 中 | 课程颗粒度 ≤15 分钟；失败激励（streak 保护卡）；提醒召回 |
